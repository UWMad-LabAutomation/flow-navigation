Robot: I2RT LinearBot FLOW holonomic base

Purpose
-------
This report records the work completed for two related tasks:

1. Apply costmap inflation to a real robot occupancy-grid map. Import a map,
   create increasing navigation costs around walls and obstacles, and deliver
   the original map, inflated costmap, and a comparison visualization.

2. Test path planning on the inflated map. Use A* or a ROS 2/Nav2 planner and
   compare paths planned on the original occupancy grid and the inflated map.
   Document the effects of inflation radius and cost values on clearance and
   route selection.

The project has a working simulated robot, Gazebo/RViz/Nav2 integration, and a
procedurally generated maze with matching Gazebo walls and an occupancy map.
It does not yet satisfy every deliverable in the two tasks. In particular, the
current map is synthetic rather than a map captured from a real robot, the
final global inflated-costmap artifact has not been exported, and a systematic
original-versus-inflated path comparison has not been completed.

Robot description and physical assumptions
-------------------------------------------

Package: src/robot_description

File: src/robot_description/urdf/flow_base.urdf.xacro

- Defines the simplified FLOW base using URDF/Xacro.
- Defines base_footprint and base_link navigation frames.
- Defines a fixed base_footprint to base_link transform.
- Defines a fixed base_link to laser_link transform.
- Uses the documented footprint dimensions: 0.751 m by 0.542 m.
- Uses an approximate base mass of 80 kg.
- Uses a provisional base height of 0.200 m because a base-only height was not
  available.
- COM is undetermined. The provisional COM is the geometric center of the
  rectangular base at z = base_height / 2.
- Inertia is calculated as a uniform rectangular solid.
- The README explicitly marks height, COM, and inertia as provisional and says
  that measured values are needed before dynamic simulation or hardware use.

This is a navigation simulation model, not a measured final dynamics model.


Gazebo simulation
-----------------

Package: src/robot_simulation

Files:

- worlds/flow_base.sdf
- launch/flow_base_sim.launch.py
- robot_simulation/maze_generator.py
- README.md

The SDF world:

- Uses Gazebo Harmonic systems and a ground plane.
- Represents the base with a 0.751 m x 0.542 m x 0.200 m chassis.
- Uses an 80 kg total approximation: 72 kg chassis plus four 2 kg wheels.
- Uses Gazebo's MecanumDrive plugin as a holonomic approximation.
- Accepts forward velocity, lateral velocity, and yaw rate.
- Uses four wheel joints and anisotropic friction to approximate mecanum
  roller behavior rather than modeling explicit rollers.
- Publishes simulated odometry and an odom to base_footprint transform.
- Includes a planar GPU lidar with 360 samples, 10 Hz update rate, and a
  0.12 m to 12.0 m range.

The simulation launch:

- Starts Gazebo.
- Starts ros_gz_bridge for /cmd_vel, /odom, /tf, and /scan.
- Runs robot_state_publisher from the Xacro description.
- Publishes the static laser frame connection required by the Gazebo sensor
  frame.

Manual simulation checks completed during development:

- Forward motion using /cmd_vel.
- Reverse motion using negative linear x.
- Lateral holonomic motion using linear y.
- In-place angular motion using angular z.
- Odometry and TF inspection with /odom, /tf, and tf2_echo.
- Direct Gazebo command testing was documented in robot_simulation/README.md.

Known simulation limitations:

- MecanumDrive and anisotropic friction are an approximation of the powered
  caster/FLOW mechanics.
- Wheel collision geometry and roller dynamics are simplified.
- Height, COM, and inertia remain provisional.
- The real I2RT FlowBaseClient/CAN bridge has not been implemented.


Maze generation and map import
-------------------------------

File: src/robot_simulation/robot_simulation/maze_generator.py

The generator:

- Uses recursive backtracking, matching the supplied Python maze algorithm.
- Defaults to a 21 x 21 odd-sized maze.
- Uses a repeatable integer seed when seed:=N is supplied.
- Defaults to 2.5 m maze cells/corridors so the base has usable clearance.
- Defaults to a 0.05 m occupancy-map resolution.
- Defaults to 0.5 m wall height.
- Writes static SDF collision and visual geometry for occupied maze cells.
- Writes a trinary PGM map and matching YAML metadata.
- Places the simulated base at the generated start cell.
- Reports the generated start and goal coordinates.

Default generated artifacts:

- /tmp/flow_maze/maze_world.sdf
- /tmp/flow_maze/maze.yaml
- /tmp/flow_maze/maze.pgm

For seed 42 with the default dimensions, the generated start and goal are
approximately:

- Start: (-22.5, 22.5)
- Goal: (22.5, -22.5)

The map verified during testing was 1050 x 1050 cells at 0.05 m/cell, with an
origin of (-26.25, -26.25). The map server reported the map as loaded and
published it on /map with frame_id map.

File: src/robot_navigation/launch/maze_navigation_launch.py

This launch file generates the maze artifacts before including the normal
navigation launch. It exposes seed, output_dir, width, height, cell_size,
resolution, wall_height, use_rviz, use_sim_time, and autostart arguments.


Navigation architecture
-----------------------

Package: src/robot_navigation

File: launch/navigation_launch.py

The normal launch starts:

- Gazebo simulation.
- map_server using the supplied map YAML.
- AMCL localization.
- controller_server.
- planner_server.
- smoother_server.
- behavior_server.
- bt_navigator.
- waypoint_follower.
- velocity_smoother.
- collision_monitor.
- Localization and navigation lifecycle managers.
- RViz using the Nav2 default view unless disabled.

Data flow:

Gazebo lidar -> /scan -> AMCL and local/global obstacle layers
Gazebo odometry -> /odom and odom -> base_footprint
robot_state_publisher -> base_footprint -> base_link and base_link -> laser_link
map_server -> /map with frame_id map
AMCL -> map -> odom after an initial pose is supplied
Nav2 global costmap -> /global_costmap/costmap
Nav2 local costmap -> local costmap topics
SmacPlanner2D -> global path
MPPI controller -> cmd_vel_nav
Velocity smoother -> cmd_vel_smoothed
Collision monitor -> /cmd_vel
ros_gz_bridge -> Gazebo MecanumDrive

The base navigation degrees of freedom are vx, vy, and yaw rate. The vertical
rail and YAM arms are outside the navigation controller scope.

RViz and TF findings
--------------------

RViz Fixed Frame must be exactly map. The /map topic and /global_costmap/costmap
topic were both verified with one publisher and an RViz subscription.

Important startup behavior:

- map_server publishing /map does not by itself create a TF frame named map.
- AMCL publishes map -> odom after receiving a 2D initial pose.
- The global costmap waits for a usable transform to base_link.
- Early "Invalid frame ID map" and transform extrapolation messages can occur
  while AMCL and the costmap start. They should resolve after the initial pose
  and TF chain are available.
- RViz's Topic OK status only confirms the configured topic name. A display
  with Width 0 and Height 0 has not received a valid OccupancyGrid yet.
- The downsampled-costmap display is not used because downsample_costmap is
  false and should be disabled in RViz.

How to reproduce the current simulation
----------------------------------------

From a clean terminal:

    cd ~/robot_ws
    source /opt/ros/jazzy/setup.bash
    colcon build --symlink-install \
      --packages-select robot_description robot_simulation robot_navigation
    source install/setup.bash
    ros2 launch robot_navigation maze_navigation_launch.py seed:=42

In RViz:

1. Set Global Options / Fixed Frame to map.
2. Add or verify Map on /map.
3. Set the initial pose near the generated start, approximately (-22.5, 22.5)
   for seed 42.
4. Verify /global_costmap/costmap is selected for the global costmap display.
5. Send a goal near the center of a known free corridor.

Useful terminal checks:

    ros2 topic info /map -v
    ros2 topic info /global_costmap/costmap -v
    ros2 topic echo /global_costmap/costmap --once
    ros2 topic echo /amcl_pose --once
    ros2 run tf2_ros tf2_echo map base_link
    ros2 lifecycle get /amcl
    ros2 lifecycle get /planner_server
    ros2 topic echo /cmd_vel
    ros2 topic echo /odom
